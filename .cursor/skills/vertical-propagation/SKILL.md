# Skill 3: Continuous Vertical Propagation and Modular 3D Development
This is the project-level skill for Skill 3 in the shared repository `livingmorphologies`.
Apply this skill when continuing a final, already selected 2D Physarum outcome into the Z dimension as a modular 3D protoarchitectural form. Do not apply it to Skill 1 translation, Skill 2 2D generation, 2D evaluation, 2D selection, architectural criteria, or final multi-module aggregation.
Current status: definition only. Skill 1 translation is complete in this repository. Skill 3 still waits for Skill 2's 15 selected 2D outcomes. Do not implement vertical-propagation code, create 3D geometry, or reconstruct Skill 1 / Skill 2 unless the user explicitly requests that work.
## Purpose
Skill 3 begins only after Skill 2 has completed the 2D generation and architectural evaluation process.
Take each selected 2D Physarum state as an initial condition and allow its generative behavior to continue vertically through the Z dimension.
Transform the 2D generative condition into a continuous 3D protoarchitectural morphology.
The resulting 3D forms must also operate as modular units capable of future connection, interlocking, and aggregation.
## Input
The input will eventually consist of 15 final selected 2D Physarum outcomes, one for each architectural archetype.
Whenever available, each selected 2D input should include:
- selected 2D section
- underlying Physarum state
- simulation parameters
- random seed
- trail data
- density data
- attractor information
- boundary information
- dimensions
- architectural source information
Prefer the underlying Physarum state and generation data over only a static image or section outline.
If the generative state is available, use it as the basis for vertical development. Do not simply extrude the visible 2D geometry.
This skill begins only after those final 2D outcomes exist, or when the user is defining this skill without requiring that input yet. Do not regenerate or re-select missing Skill 2 outcomes.
## Vertical Propagation
Conceptual workflow:
```
SELECTED 2D PHYSARUM STATE
        ↓
INITIAL Z CONDITION
        ↓
CONTINUOUS VERTICAL PROPAGATION
        ↓
SUCCESSIVE Z STATES
        ↓
CONTINUOUS 3D MORPHOLOGY
        ↓
MODULAR PROTOARCHITECTURAL FORM
```
Each vertical state should inherit information from the previous state.
Conceptually:
```
Z0
→ inherits + evolves
→ Z1
→ inherits + evolves
→ Z2
→ inherits + evolves
→ Z3
→ ...
→ 3D morphology
```
The system should eventually support:
- vertical growth
- inheritance
- branching
- convergence
- divergence
- continuity
- persistence
- gradual transformation
- controlled variation
The 3D form must emerge from continued generative behavior.
The Z dimension must behave as a continuation of the Physarum process.
## This Is Not
- simple extrusion
- conventional lofting
- stacking unrelated sections
- independent random layers
- arbitrary 3D geometry
Do not replace continued Physarum behavior with those operations.
## Protoarchitectural Interpretation
The resulting 3D geometry should remain abstract and protoarchitectural.
Do not automatically assign:
- rooms
- walls
- floors
- stairs
- furniture
- conventional program
- predetermined architectural objects
The morphology should remain a spatial consequence of the generative process.
## Modularity
Every final 3D result should function as an independent module.
The module should be capable of future:
- connection
- interlocking
- repetition
- transformation
- aggregation
The system should eventually consider:
- module boundaries
- connection zones
- compatible connection conditions
- repeatable connection logic
- continuity between connected modules
Do not define a specific physical joint system yet.
Do not automatically create:
- male / female connectors
- tabs
- slots
- mechanical joints
- fabrication details
unless those conditions are defined later.
## Modularity During Growth
Modularity should influence the morphology while it is being generated.
It should not simply be added afterward as an unrelated operation.
Possible future modular constraints may influence:
- bounding regions
- connection zones
- edge conditions
- growth direction
- density near connection areas
- module dimensions
- continuity points
However:
```
PHYSARUM BEHAVIOR
```
must remain the primary generative logic.
Modularity constrains the growth. It does not replace the growth.
Conceptually:
```
PHYSARUM LOGIC
+
MODULAR CONSTRAINTS
        ↓
MODULAR 3D MORPHOLOGY
```
## Handoff / Future Stage
Skill 3 ends with independent modular 3D protoarchitectural forms.
Actual multi-module interlocking and larger aggregation belongs to a later stage of the project.
Until implementation is requested, this skill's only deliverable is this definition.
## This Skill Must Not
- generate the original 2D sections
- evaluate 2D iterations
- select final 2D outcomes
- modify architectural criteria
- rewrite architectural descriptors
- redo Skill 1
- redo Skill 2
- simply extrude the section
- loft unrelated sections
- generate arbitrary 3D geometry
- automatically assign architectural program
- perform final multi-module aggregation yet
- invent a fixed connection system before one is defined
## Agent Rules
- Treat the selected 2D outcome as given.
- Do not regenerate or re-select it.
- Use underlying Physarum state data whenever available.
- Continue the generative behavior through Z.
- Preserve inheritance between successive states.
- Keep resulting geometry protoarchitectural.
- Produce independent modular 3D outcomes.
- Allow modular constraints to influence growth without replacing Physarum.
- Leave actual aggregation for a future stage.
- Stay strictly inside Skill 3.
- When implementation is requested, implement only vertical propagation and modular 3D development. Do not generate 2D sections, re-evaluate them, or leave this skill's boundary.
